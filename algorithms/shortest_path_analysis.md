# Кратчайший путь (Shortest Path) в сетях

## 1. Введение и теоретические основы

Кратчайший путь (англ. *shortest path*) — это фундаментальная операция сетевого анализа, направленная на **определение оптимального маршрута между двумя точками в линейной сети** с учётом заданных критериев оптимизации (расстояние, время, стоимость). Данная операция реализует классические алгоритмы теории графов, такие как **Дейкстры (Dijkstra, 1959)** или **A\***, и применяется к векторным данным, структурированным как **топологическая сеть**.

С математической точки зрения, сеть представляется как граф \( G = (V, E) \), где:
- \( V \) — множество вершин (перекрёстков, остановок),
- \( E \) — множество рёбер (дорог, улиц, трубопроводов),
- каждому ребру \( e_i \) присвоен вес \( w_i \) (длина, время в пути, тариф).

Задача shortest path заключается в поиске последовательности рёбер между узлами \( s \) (источник) и \( t \) (назначение), минимизирующей суммарный вес:
\[
P^* = \arg\min_{P \in \mathcal{P}(s,t)} \sum_{e \in P} w(e)
\]

В контексте геоинформационных систем данная операция служит основой для:
- маршрутизации транспорта и пешеходов,
- планирования логистических цепочек,
- анализа доступности объектов инфраструктуры,
- моделирования потоков в коммунальных сетях.

Методологически shortest path относится к классу **сетевых (network-based) операций**, требующих предварительной **топологической подготовки данных**.

## 2. Ключевые слова и семантические триггеры

кратчайший путь, shortest path, маршрутизация, сетевой анализ, QGIS Shortest Path, ArcMap Network Analyst

## 3. Область применения

- **Транспорт**: расчёт оптимального маршрута автомобиля от точки А до Б.
- **Логистика**: планирование доставки товаров с учётом времени и пробок.
- **Градостроительство**: оценка пешеходной доступности школ, больниц, парков.
- **Коммунальное хозяйство**: поиск кратчайшего пути для прокладки кабеля или трубы.
- **Туризм**: построение пеших маршрутов по городу или природному парку.
- **Экстренные службы**: расчёт времени прибытия скорой помощи или пожарной машины.

## 4. Входные данные

- **Сетевой слой**: линейный векторный слой (дороги, улицы, тропы), **топологически корректный** (линии соединены в узлах).
- **Атрибут стоимости**: числовой атрибут (например, `length`, `time_min`, `cost`), по которому оптимизируется путь.
- **Точки начала и конца**: либо интерактивный выбор на карте, либо заранее подготовленные точечные слои.
- **Направленность**: указание, является ли сеть ориентированной (одностороннее движение).

> ⚠️ **Важно**: Линии должны быть **разорваны в местах пересечений**, чтобы образовывать корректные узлы. Иначе маршрут не сможет «повернуть».

## 5. Выходные данные

- Новый **линейный векторный слой**, содержащий геометрию оптимального маршрута.
- Атрибутивная таблица с полями:
  - `total_cost` — суммарная стоимость пути,
  - `start_node`, `end_node` — идентификаторы узлов,
  - `path_order` — порядок следования сегментов.
- Возможность экспорта в форматы GPX, KML для навигационных устройств.

## 6. Программная реализация

### 6.1. QGIS (версия 3.28+)
- **Путь**: Анализ сети → Кратчайший путь (точка к точке)...
- **Параметры**:
  - Vector layer representing network: слой дорог,
  - Path type to calculate: кратчайший / самый быстрый,
  - Optimization attribute: атрибут стоимости (например, `time_min`),
  - Start point / End point: выбор на карте или из слоя.
- **Особенности**: 
  - Не требует предварительного построения топологии — работает «на лету»,
  - Поддерживает одностороннее движение через атрибут `direction`,
  - Результат можно сразу визуализировать и экспортировать.

### 6.2. ArcMap (версии 10.4–10.8)

Инструмент **Shortest Path** доступен через расширение **Network Analyst**, которое должно быть активировано (*Customize → Extensions → Network Analyst*).

#### Этапы работы:
1. **Создание сетевого набора данных (Network Dataset)**:
   - В ArcCatalog: ПКМ по geodatabase → New → Network Dataset,
   - Указание исходного линейного слоя,
   - Настройка атрибутов стоимости (длина, время),
   - Построение топологии.
2. **Анализ маршрута**:
   - Открыть Network Analyst → New Route,
   - Добавить точки начала и конца (Stops),
   - Нажать Solve.

#### Особенности версий 10.4–10.8:
- В ArcMap 10.4–10.6 интерфейс Network Analyst менее интуитивен.
- Начиная с 10.7, улучшена производительность при работе с большими сетями (>100 000 рёбер).
- Требуется **File Geodatabase** для создания Network Dataset.
- Поддерживает сложные ограничения: повороты, высотные ограничения, часовые пояса.

#### Типичные сценарии:
- **Автомобильная маршрутизация**:  
  Сеть = дороги.shp, Стоимость = `time_min` → Маршрут с учётом скорости.
- **Пешеходный маршрут**:  
  Сеть = тропы.shp, Стоимость = `length` → Кратчайший путь по парку.

## 8. Ограничения и особенности

1. **Требование к топологии**: линии должны быть корректно соединены в узлах.
2. **Производительность**: время расчёта растёт с увеличением размера сети.
3. **Однократный путь**: стандартный shortest path не решает задачу коммивояжёра (TSP) — для этого нужны другие инструменты.
4. **Динамические данные**: не учитывает реальное время (пробки, аварии) без внешних API.
5. **ArcMap-зависимость**: Network Analyst недоступен в базовых лицензиях (только Standard/Advanced).
