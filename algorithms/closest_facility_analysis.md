# Ближайший объект (Closest Facility)

## 1. Введение и теоретические основы

Ближайший объект (англ. *closest facility*) — это операция сетевого анализа, направленная на **определение одного или нескольких ближайших «объектов обслуживания» (facilities) для каждой «точки запроса» (incidents) с учётом реальной топологии сети и заданного критерия стоимости** (расстояние, время, топливо). В отличие от OD Cost Matrix, которая строит полную матрицу, Closest Facility фокусируется только на **наилучшем (или N лучших) вариантах**, что делает его оптимальным для задач экстренного реагирования и логистики.

С математической точки зрения, задача сводится к поиску для каждой точки запроса \( I_i \) такого объекта \( F_j \), который минимизирует стоимость пути:
\[
F^* = \arg\min_{F_j \in \mathcal{F}} \text{cost}(I_i \rightarrow F_j)
\]

В контексте геоинформационных систем данная операция служит ключевым инструментом для:
- расчёта времени прибытия экстренных служб (скорая, пожарные),
- определения ближайшего магазина, школы или больницы для пользователя,
- оптимизации размещения новых объектов инфраструктуры,
- моделирования поведения потребителей в розничной торговле.

Методологически Closest Facility относится к классу **сетевых (network-based) операций** и реализуется на основе алгоритмов кратчайшего пути (например, Дейкстры).

## 2. Ключевые слова и семантические триггеры

ближайший объект, closest facility, ближайшая больница, ближайший магазин, QGIS Closest Facility, ArcMap Network Analyst

## 3. Область применения

- **Экстренные службы**: определение ближайшей пожарной части для происшествия.
- **Здравоохранение**: поиск ближайшей больницы для пациента.
- **Розничная торговля**: рекомендация ближайшего магазина клиенту.
- **Градостроительство**: оценка доступности социальных объектов для жителей.
- **Логистика**: назначение ближайшего курьера на заказ.
- **Туризм**: поиск ближайшей гостиницы или туалета для туристов.

## 4. Входные данные

- **Сетевой слой**: линейный векторный слой (дороги, улицы), **топологически корректный**.
- **Атрибут стоимости**: числовой атрибут (например, `time_min`, `length`).
- **Точки запроса (Incidents)**: точечный слой (аварии, пациенты, клиенты).
- **Объекты обслуживания (Facilities)**: точечный слой (больницы, магазины, склады).
- **Число ближайших объектов**: сколько объектов найти для каждой точки (по умолчанию — 1).
- **Направление**: от инцидента к объекту или наоборот (важно для односторонних дорог).

> ⚠️ **Важно**: Точки должны быть **привязаны к сети** (snap to network). Иначе расстояние будет рассчитано некорректно.

## 5. Выходные данные

- **Линейный слой маршрутов**: геометрия оптимальных путей от каждой точки запроса к ближайшему объекту.
- **Таблица результатов** с полями:
  - `IncidentID` — идентификатор точки запроса,
  - `FacilityID` — идентификатор ближайшего объекта,
  - `Total_Cost` — стоимость пути (время, расстояние),
  - `Rank` — порядковый номер (если запрошено >1 объекта).
- Возможность экспорта в GPX, KML или таблицу.

## 6. Программная реализация

### 6.1. QGIS (версия 3.28+)
- **Путь**: Анализ сети → Ближайший объект...
- **Параметры**:
  - Vector layer representing network: слой дорог,
  - Incident points: точки запроса,
  - Facility points: объекты обслуживания,
  - Optimization attribute: атрибут стоимости,
  - Number of facilities to find: количество ближайших объектов.
- **Особенности**: 
  - Не требует предварительного построения топологии,
  - Поддерживает привязку точек к сети,
  - Результат — маршруты и таблица.

### 6.2. ArcMap (версии 10.4–10.8)

Инструмент **Closest Facility** доступен через расширение **Network Analyst**, которое должно быть активировано (*Customize → Extensions → Network Analyst*).

#### Этапы работы:
1. **Создание сетевого набора данных (Network Dataset)**.
2. **Анализ ближайшего объекта**:
   - Открыть Network Analyst → New Closest Facility,
   - Добавить Incidents и Facilities,
   - Указать Impedance (например, `Time`),
   - Задать число объектов (`Default number of facilities to find`),
   - Нажать Solve.

#### Особенности версий 10.4–10.8:
- В ArcMap 10.4–10.6 интерфейс менее интуитивен.
- Начиная с 10.7, улучшена производительность и поддержка обратного направления (от объекта к инциденту).
- Требуется **File Geodatabase** для создания Network Dataset.
- Поддерживает **ограничение по времени/расстоянию** (Cutoff).

#### Типичные сценарии:
- **Пожарная безопасность**:  
  Incidents = пожары.shp, Facilities = пожарные части.shp → Ближайшая часть для каждого пожара.
- **Здравоохранение**:  
  Incidents = вызовы скорой.shp, Facilities = больницы.shp → Ближайшая больница.

## 8. Ограничения и особенности

1. **Требование к топологии**: линии должны быть корректно соединены в узлах.
2. **Производительность**: время расчёта растёт линейно с числом точек.
3. **Привязка точек**: если точки не попадают точно на сеть, используется автоматическая привязка.
4. **Направленность**: важно указать правильное направление (особенно при одностороннем движении).
5. **ArcMap-зависимость**: Network Analyst недоступен в базовых лицензиях (только Standard/Advanced).
