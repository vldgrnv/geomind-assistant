# Сводная таблица (Pivot Table)

## 1. Введение и теоретические основы

Сводная таблица (англ. *pivot table*) — это операция агрегации атрибутивных данных, направленная на **группировку записей по одному или нескольким категориальным признакам с последующим вычислением статистических показателей** (сумма, среднее, количество и др.) для количественных полей. В отличие от простой фильтрации или выборки, pivot table позволяет свести многомерные данные к компактной двумерной форме, удобной для анализа и визуализации.

С методологической точки зрения, сводная таблица реализует принцип **OLAP-анализа (Online Analytical Processing)** над атрибутивными таблицами ГИС. Она преобразует «длинный» формат данных (по одной записи на объект) в «широкий» (по одной строке на уникальную комбинацию категорий), где:
- строки соответствуют уникальным значениям одного поля (например, `район`),
- столбцы — уникальным значениям другого поля (например, `тип_землепользования`),
- ячейки содержат агрегированные значения (например, суммарная площадь).

В контексте геоинформационных систем сводные таблицы служат ключевым инструментом для:
- анализа распределения землепользования по районам,
- оценки демографической структуры по возрастным группам и территориям,
- сравнения объёмов выбросов по отраслям и регионам,
- подготовки данных для диаграмм и картограмм.

Методологически данная операция относится к классу **атрибутивных агрегаций** и является мостом между ГИС и табличными процессорами.

## 2. Ключевые слова и семантические триггеры

сводная таблица, pivot table, агрегация данных, группировка, QGIS Pivot Table, ArcMap Summary Statistics

## 3. Область применения

- **Градостроительство**: анализ площади землепользования по функциональным зонам и районам.
- **Демография**: расчёт численности населения по возрасту и полу в разрезе территорий.
- **Экология**: суммарные выбросы по отраслям и муниципалитетам.
- **Экономика**: ВРП по секторам экономики и регионам.
- **Сельское хозяйство**: площадь посевов по культурам и хозяйствам.
- **Логистика**: объём перевозок по направлениям и типам грузов.

## 4. Входные данные

- **Векторный слой** (обычно полигональный или точечный).
- **Атрибутивная таблица**, содержащая:
  - как минимум одно **категориальное поле** (для группировки),
  - как минимум одно **количественное поле** (для агрегации).
- **Поля группировки**: одно или два (для двумерной таблицы).
- **Функция агрегации**: сумма, среднее, количество, максимум, минимум.

> ⚠️ **Важно**: Для корректной агрегации количественные поля не должны содержать пустых значений (NULL). Рекомендуется предварительно выполнить очистку данных.

## 5. Выходные данные

- **Таблица** (в формате DBF, CSV или geodatabase table).
- Структура:
  - Первая колонка — уникальные значения первого поля группировки,
  - Последующие колонки — уникальные значения второго поля (если задано),
  - Ячейки — агрегированные значения (например, суммарная площадь).
- Возможность импорта обратно в ГИС для присоединения к слоям или экспорта в Excel.

## 6. Программная реализация

### 6.1. QGIS (версия 3.28+)
- **Путь**: Обработка → Инструментарий анализа → Сводная таблица...
- **Параметры**:
  - Input layer: исходный слой,
  - Group by: первое поле группировки (например, `"district"`),
  - Pivot field: второе поле (например, `"land_use"`),
  - Aggregation function: `sum`, `mean`, `count` и др.,
  - Aggregation field: количественное поле (например, `"area"`),
  - Output: путь к выходной таблице.
- **Особенности**: 
  - Поддерживает двумерные таблицы «поле × поле»,
  - Результат можно сразу открыть в QGIS или экспортировать в CSV,
  - Автоматически обрабатывает NULL-значения (игнорирует).

### 6.2. ArcMap (версии 10.4–10.8)

В ArcMap **нет прямого инструмента «Pivot Table»**, но его функционал достигается через:

#### Вариант A: **Summary Statistics**
1. Откройте **ArcToolbox**.
2. Перейдите: **Analysis Tools → Statistics → Summary Statistics**.
3. Укажите:
   - Input Table: атрибутивная таблица,
   - Statistics Field(s): количественное поле + функция (SUM, MEAN и т.д.),
   - Case Field(s): поле(я) группировки.
4. Результат — одномерная сводка (не двумерная).

#### Вариант B: **Использование Python-скрипта**
- Через **Field Calculator** или отдельный скрипт на основе `pandas.pivot_table`.
- Требует установки Python и библиотеки pandas.

#### Особенности версий 10.4–10.8:
- ArcMap не поддерживает двумерные сводные таблицы «из коробки».
- Для полноценного pivot table рекомендуется экспортировать таблицу в **Excel** или использовать **QGIS**.
- Summary Statistics даёт только список (не матрицу), но достаточен для многих задач.

#### Типичные сценарии:
- **Землепользование**:  
  Слой = участки.shp, Группировка = `район`, Сводка = `SUM("area")` → площадь по районам.
- **Демография**:  
  Слой = дома.shp, Группировка = `возраст_группа`, Сводка = `SUM("population")`.

## 8. Ограничения и особенности

1. **ArcMap-ограничение**: отсутствие двумерных сводных таблиц без внешних инструментов.
2. **Производительность**: время выполнения растёт с увеличением числа уникальных категорий.
3. **Потеря геометрии**: результат — чисто атрибутивная таблица, без привязки к объектам.
4. **Требования к данным**: наличие категориальных и количественных полей.
5. **Интерпретация**: сводка не заменяет пространственный анализ — она дополняет его.

## 9. Научно-методическое обоснование

Сводные таблицы восходят к концепции OLAP, предложенной Codd (1993), и широко применяются в аналитике. В ГИС они реализуют принцип **агрегации пространственных данных по атрибутивным измерениям**, описанный в работах Longley et al. (*Geographic Information Science & Systems*, 2015). Они соответствуют стандарту ISO 19101 (модель пространственных данных).
